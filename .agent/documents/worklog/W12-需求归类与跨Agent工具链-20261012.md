### 4.2 目录合并可行性（已实测）

**结论：合并到 `D:\Ai Program\` 不影响 git，但会触发重建。**

实测依据：
- 两项目**各自独立仓库 + 独立 remote**（`SummonerLens.git` / `mangrove.git`），互不干扰
- git 只关心仓库内部结构，父目录名无关

风险项：
| 风险 | 具体情况 | 影响 |
|---|---|---|
| **构建缓存绝对路径** | `SummonerLens/app/build/windows/x64/CMakeCache.txt` 等；`Mangrove/Mangrove/.dart_tool/flutter_build/`、`build/windows/x64/` | 移动后失效，需清缓存重建 |
| **IDE 配置** | TRAE/VSCode 记住的项目路径 | 需重开项目 |
| **Dart 通道故障** | 用户当前沙盒 Dart `CreateFile failed 231` 未恢复 | 重建成本被放大 |

**建议：现在别动**。等手头项目阶段收尾、构建稳定后再整理，或接受重跑一次构建。

| ID | 要求 | 状态 |
|---|---|---|
| E-1 | 调研是否存在跨 agent 通用的沙盒浏览器方案 | 🔄 进行中 |
| E-2 | 建立用户专属工具仓库（跨项目/跨会话/跨 agent） | 🔄 待设计 |

**已知约束（本轮确认）：**
- `agent-browser` CLI 全局安装后，**本机所有项目、所有 WorkBuddy 会话可共用**
- 但**不跨 agent 平台**（TRAE 的内置浏览器 WorkBuddy 用不了，反之亦然）
- TRAE 与 WorkBuddy 各自一套 ⇒ 磁盘重复（约 0.5G/套），能力不互通
- C: 剩 51G / D: 剩 817G，空间充裕

**核心洞察（待验证）：** TRAE 的内置浏览器是**平台内置沙盒**（只有该平台 agent 能调）；
而 **CLI / MCP 驱动的浏览器是"外部进程"**——任何具备本机 shell 执行能力的 agent 都能驱动同一实例。
这正是「跨 agent 浏览器」的理论可行路径。详见本轮回复正文。
