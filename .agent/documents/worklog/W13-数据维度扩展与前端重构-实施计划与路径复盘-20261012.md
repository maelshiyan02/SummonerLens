## 2. 阶段 A 详细计划与执行

### A1 fetch_resg.py — RESG ETL 抓取脚本

**计划要点**：
- 端点：`https://resg.top/api/v1/versions/<ver>/{champions,augments}.js`
- ES module 剥离：正则 `r'^export\s+default\s+'`（而非简单 `.replace()`）
- curl 优先（`curl.exe -sSL --noproxy '*'`），回退 urllib
- 落盘结构：`data/agg_resg/<ver>/{champions,augments,citation}.json` + `LATEST` 指针
- 字段契约：英雄 ≥150 条、海克斯 ≥180 条；wr 与 wm/tm 一致性抽样

**执行结果**：✅ 173 英雄 / 211 海克斯 / wr 抽样 30 条一致 / citation.json 四字段齐备

### A2 装备数据源探查 — 如实报告数据缺口

**计划要点**：
- 尝试 RESG 可能的 8 种装备端点变体（items.js / item-stats.js / champion-items.js 等）
- 同时查 hexdata 是否有装备维度

**执行结果**：
- RESG 8 种变体全 404
- hexdata 也无装备维度
- 决策：**如实标注数据缺口**。先展示 A12 元数据装备列表（870 件含模式归属），聚合胜率等数据源出现后接入

**经验教训**：数据缺口不要硬填或臆造。resg/hexdata 均未开放装备聚合端点时，应走「方案 3 —— 元数据占位 + 说明」，而非空数据集或假数据。

### A3 DuckDB RESG 表 — 独立 loader，不改整库重建

**计划要点**：
- 新建函数 `build_resg_tables(con, root)`，作为 main() 的第四路追加
- 新表 `agg_resg_champions` + `agg_resg_augments`
- 强制带溯源列：`_source` / `_confidence` / `_asof` / `_collected_at`

**执行结果**：✅ verify_pipeline.py 68/0 零回归

**关键决策**：独立 loader 而非集成到既有三路重建逻辑。理由：
1. 既有 `build_duckdb.py` 三路（hexdata / meta / agg）每次全删全建，改它风险大
2. 独立函数可单独跑，便于增量更新
3. 如果 RESG 数据拉取失败，不影响既有三表

### A4 build_viz_bundle.py — 三数据集，schema 保持 v1

**计划要点**：
- 新增 `load_resg_prov()` + `load_resg_rankings()`
- 3 个新数据集：
  - `resg_champions`：173 行，Wilson 排序 + 样本分档 + 推荐级
  - `resg_augments`：211 行，quality + top_champions + rarity
  - `resg_items`：先 `kind=unavailable`，留待修补
- roles 英文转中文（role_zh_map）
- 复用 `stats/wilson.rank_entities()` 排序内核

**执行结果**：
- 英雄/海克斯数据集正确生成
- **隐藏 bug**：`load_resg_rankings` 内部 `ver = latest.read_text().strip()` 覆盖了函数参数 `ver`，导致 items_modes.csv 路径拼接用的是 RESG 版本号（16.20）而非 meta 版本号（16.20.1）。items 文件不在 16.20 下，落入 else 分支 → kind=unavailable
- 修补 commit `8ffb8f1` 才把 items 修好（重命名内部变量为 `resg_ver`）

## 5. 关键架构决策一览

| 决策 | 选择 | 理由 |
|------|------|------|
| schema 版本 | **保持 v1** | verify_m4.py + test_m4_unit.js 硬编码检查 v1，升版引发级联失败 |
| ES module 剥离 | 正则 `r'^export\s+default\s+'` | 官方推荐，兼容空格/换行 |
| RESG kind | `real_aggregate_resg` | 与 hexdata `real_aggregate` 同级但独立标识 |
| 装备维度 | `real_metadata`（870 件） | RESG/hexdata 无聚合胜率端点，如实标注缺口 + 展示可用元数据 |
| Wilson 复用 | 直接调 `stats/wilson.rank_entities()` | 已有经过 M3 反霸榜验证的排序内核 |
| 前端 entity 切换 | RESG panel 内嵌 seg 按钮 | 不污染旧排名面板的 seg 逻辑 |
| 表头排序 | 事件委托 `tbl.onclick` | 行 DOM 重绘后事件仍生效 |
| 低样本警示 | CSS class `tier-row-low` | 纯视觉区分，不改变数据本身 |
| DuckDB RESG loader | 独立函数追加 | 不修改既有三路重建逻辑，降低风险 |
