# W10 · 前端版本化与趋势视图（M5-4）

> 日期：2026-10-11｜前置：M5-1（注册表）、M5-2（跨版本内核）、M5-3（落库）
> 目标：把「版本可切换、变更可查看、趋势可画、来源可溯」落到离线仪表板（app/web）。

## 1. 数据束扩展（python/bridge/build_viz_bundle.py）

新增 5 个离线可直接消费的 M5 字段（不依赖运行时扫目录）：

| 字段 | 内容 | 来源 |
|---|---|---|
| `versions` | `data/versions.json` 全量注册表 | M5-1 |
| `metas` | 全部 meta 版本的英雄字典 `{ver:{heroes:[…]}}` | Data Dragon |
| `version_changes` | 相邻 meta 版本两两 `trend.diff_meta` 结果列表 | M5-2 |
| `trend` | 英雄胜率跨 build 序列；≥2 快照→`real_aggregate`，否则→`synthetic_fixture` | M5-3 + 合成 |
| `risk_notes` | hexdata `methodology.json` 的 riskNotes（3 条） | hexdata |

- `load_hero_meta` 对缺失 `aliases.csv` 容错（16.19.1 缺该文件）。
- `build_aggregate_trend`：agg 仅 1 快照时，`_synthesize_trend` 以**单份真实数据 + 确定性 ±0.03 扰动**生成 3 个 build 演示序列，明确 `synthetic_fixture`；不伪造真实趋势。
- `economy_leaders`（既有 10 条）继续保留。

**实测数据束**：658,823 字节；`metas` 含 16.19.1/16.20.1（各 173 英雄）；`version_changes` 1 对（16.19.1→16.20.1，7 英雄变更，真实）；`trend.kind=synthetic_fixture`（3 builds）；`risk_notes` 3 条。

## 2. 前端（app/web）

### 2.1 index.html
- 顶栏新增**版本选择器** `<select id="sel-ver">`（从 `versions` 的 meta 快照填充，标注「最新」）。
- 新增标签页「**版本 / 趋势**」（`data-tab="version"`）+ 面板 `#panel-version`（版本变更卡 + 聚合趋势卡）。
- 概览新增「经济强度榜」「分析风险备注」两张卡片（顺带接入已抓未展示维度 economyRanking / riskNotes）。

### 2.2 js/core.js（纯函数，可 node 单测）
- `heroNameInMeta(bundle, key, ver)`：选定版本英雄名解析（离线切换）。
- `buildChangesSummaryOption(summary)`：新增/移除/变更 计数条形图（5 类目，装备移除着红）。
- `buildTrendOption(trend, nameMap)`：多英雄胜率跨 build 折线（取末 build 胜率前 8，x=report_date，y=winRate）。
- `emptyOption(text)`：空图表占位（core.js 内置，headless 单测可用）。
- 上述 4 个均加入导出面。

### 2.3 js/app.js
- `state.metaVersion` 驱动：名称/别名解析（`nameOf`/`buildMetaMap`）、版本变更对比目标、`?ver=` 深链。
- `sel-ver` 切换 → 更新 `state.metaVersion` + `history.replaceState(?ver=)` + `apply()`。
- `renderVersion()`：版本变更摘要图 + 变更明细表（类型/英雄/改动字段标签）；聚合趋势折线。
  - `trend.kind==synthetic_fixture` → 琥珀色横幅「演示（合成）· 当前 1/2 真实快照」，图表照常绘制（机制验证）。
  - `trend.kind==real_aggregate` → 蓝色横幅「真实聚合 · N 份快照」。
  - 选定版本为最早快照（无 `to` 对）→ 「无更早版本可对比」。
- `renderOverview` 补经济榜 + 风险备注；`renderChrome` 的 `pill-meta` 显示选定版本。

## 4. 已知边界 / 下一步

- **聚合趋势当前为合成演示**：hexdata 线上 `buildId` 仍未更新（M5 规划实测），真实趋势需 M5-5 定时抓取积累 ≥2 份 agg 快照后自动替换（`trend.kind` 翻转 `real_aggregate`）。
- 版本选择器切换的是**名称/别名解析 + 版本变更视图目标**（离线单束约束下，主排名的真实聚合数据仍来自 hexdata 单一 patch）；此语义已在代码注释与横幅中声明。
- 待办：M5-5 自动化积累（`sync_snapshots.py` + 定时任务）；M5-6 `verify_m5.py` + A16 收口。
- 前端改动需用户在本地 `build_desktop.bat` 重建 exe 验证（沙盒 Dart 通道故障未恢复）。

## 5. 用户手动验证（2026-10-11 收尾）

- 用户本地双击 `build_desktop.bat` 重建 → `run_desktop.bat` 启动，**人工验证通过**：版本选择器与「版本/趋势」标签**可切换**、趋势视图**可渲染**。
- **已知现象（用户反馈，属预料范围，暂不过度在意）**：运行时**仅 16.20.1 一个版本的标签与数据可用**，因此版本选择器虽能触发 `?ver=` 深链，但**没有第二份版本数据集可供对比切换**（版本变更视图只有「无更早版本可对比」、趋势为 `synthetic_fixture` 单 patch 演示）。
  - 根因：真实多版本对比依赖 ≥2 份 meta **且** ≥2 份 agg 快照；当前 `data/meta/` 虽有 16.19.1/16.20.1 两版注册，但 UI 实际可对比数据仅单一可用版本 ⇒ 待 **M5-5** 定时抓取积累更多快照后自然具备切换对比能力。
  - 判定：UI 机制已验证可用，数据不足是规划中已预见、非代码缺陷，不阻塞后续。
