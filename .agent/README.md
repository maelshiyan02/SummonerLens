# .agent · 多 agent 共享工作区（SummonerLens）

> **这是本仓库所有 AI agent 相关数据的唯一真身。**
> WorkBuddy 的 `.workbuddy/` 是本工具的本地运行目录，**不**作为项目记忆载体 —— 项目记忆只放这里。

## 目录职责

| 路径 | 放什么 |
|---|---|
| `memory/MEMORY.md` | **主记忆（≤3K 字符）**：框架 + 索引 + 底线。唯一被自动注入的文件 |
| `memory/appendices/` | 编号附录 `A01~A0x`（项目事实）+ `W00`（工作日志编号索引） |
| `memory/YYYY-MM-DD.md` | 每日工作日志（**只追加**） |
| `documents/` | 调研 / 计划 / 工作日志本体 |
| `documents/00-前期调研.md` | 项目启动前已完成的整合调研（迁移自 WorkBuddy_store） |
| `documents/plans/` | 计划类文档 |
| `documents/worklog/` | 历史工作日志本体 |
| `kb/` | **跨项目可复用**的知识库（当前：`methodology/` M01~M11） |
| `specs/` | 规格 |
| `skills/` | 技能 |

**分工**：`memory/` = 本项目的事实；`kb/` = 能带走的方法。

## 给 AI agent 的读取顺序

1. 先读 **`memory/MEMORY.md`**（框架 + 索引 + 底线）。
2. 动手前，按索引里的「触发时机」读对应附录 `memory/appendices/A0x`。
3. 做**设计/验证/交接**类决策时，读 **`kb/INDEX.md`** 挑对应方法论。
4. 查历史决策来龙去脉，看 **`memory/appendices/W00-工作日志索引.md`**。

## 🔴 两条纪律

1. **绝不写绝对路径。** 项目根目录**将来可能改名**。用相对路径；脚本必须由**自身位置**推导根目录。
2. **与 mangrove 严格隔离。** 本项目与大工作区内同级目录 `../Mangrove` 是不同的仓库/工作区/记忆体系，禁止互相改文件。

## 记忆防截断规则（硬性）

- 主记忆 `MEMORY.md` ≤ 3K 字符，只放框架与索引。
- 正文一律下沉到编号附录 `A01~A0x`；主文件 ↔ 附录**双向链接**（主文件列附录路径+摘要，附录开头回指主文件）。
- 附录单篇超 ~8K 字符就再拆，保持「一篇一个主题 + 明确触发时机」。
- 每轮有实质产出，回写 `.agent` 记忆（需要时拆附录 + 建链接）。

## 接入新的 AI agent

1. 让它直接读 `.agent/` 即可；
2. 若它默认读其它目录名（如 `.workbuddy`、`docs`），再为所需子目录建**目录联接（junction / symlink）**指向 `.agent/` 对应目录；
3. 联接存的是绝对路径，**项目根改名后必须重建**。
