# A06 · 多 Agent 记忆机制

> 上级索引：`MEMORY.md` §1（A06）｜触发时机：接入新对话、整理记忆、收尾之前｜相关：A01 身份、A05 Git

## 1. 为什么是 `.agent` 而非单 `.workbuddy`

- 本项目将**多个 AI Agent 交替开发**，不靠单个 `.workbuddy` 文件夹集中记忆/技能/文件。
- 各 Agent 的上下文与产出靠**工作区内的项目记忆文件**（`.agent/`）承接，范式参考 mangrove 的 `.agent`（见大工作区内同级目录 `../Mangrove/.agent` 作样本，但内容独立）。
- WorkBuddy 的 `.workbuddy/` 仅作本工具运行目录，**不**作为项目记忆载体（已写入 `.gitignore`）。

## 2. 防截断规则（硬性）

- 主记忆 `MEMORY.md` ≤ 3K 字符，只放框架 + 索引 + 三条底线。
- 正文一律下沉到**编号附录** `A01~A0x`；主文件 ↔ 附录**双向链接**：
  - 主文件列出附录路径 + 内容摘要；
  - 附录开头回指主文件（见各附录「上级索引」行）。
- 附录单篇超 ~8K 字符就**再拆**，保持「一篇一个主题 + 明确触发时机」。
- 切忌把所有细节堆在单一文件导致被截断丢失（mangrove 实测 ~7.2K 处静默截断）。

## 3. 读取顺序（给承接 Agent）

1. 粘贴「新对话开场白」作上下文；
2. 读 `MEMORY.md`（框架 + 索引 + 底线）；
3. 按索引「触发时机」读对应附录 `A0x`；
4. 设计/验证/交接类决策读 `kb/INDEX.md` 挑方法论；
5. 查历史决策看 `W00-工作日志索引.md`。

## 4. 回写纪律

- 每轮有**长期价值的结论、决策、踩坑**，必须回写 `.agent` 记忆（主文件或对应附录）。
- 每日工作日志：`.agent/memory/YYYY-MM-DD.md` **只追加不覆盖**；并在 `W00` 登记编号。
- 需要拆附录时同步更新 `MEMORY.md` 索引表，保持双向链接。
