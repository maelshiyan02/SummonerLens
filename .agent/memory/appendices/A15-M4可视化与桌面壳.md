# A15 · M4 可视化与桌面壳

> 上级索引：`MEMORY.md` §1（A15）｜触发时机：改仪表板/图表/桌面壳/本地服务、做前端可视化之前｜相关：A03 技术栈、A14 统计内核、A13 数据管道、M11/M12 断言纪律

## 1. 范围

在 M3（统计与建模内核）之上落地**可视化与桌面壳**：Flutter Desktop 主壳 + 内嵌 WebView2 + 离线 ECharts 仪表板 +
`bridge/` 调本地 Python 出图；深色默认主题、筛选器联动数据层、别名词典搜索、自动刷新。

## 2. 三层架构（唯一真相）

```
Flutter Desktop 壳 (app/lib)                    ← 导航 / 筛选 / 别名搜索 / 深色主题 / 自动刷新
      │ 拉起并监听 stdout marker
      ▼
Python bridge (python/bridge/serve.py)          ← 仅绑 127.0.0.1 的本地 HTTP；提供静态资源 + /api/health + /api/rebuild
      │ 装载
      ▼
ECharts 仪表板 (app/web)                        ← 离线（vendor/echarts.min.js）、单一数据源 data/dashboard.json
      ▲
      │ 由 python/bridge/build_viz_bundle.py 聚合 M1~M3 产物生成
```

**为什么走「本地 HTTP」而不是直接 `file://`**：webview 以 `file://` 打开页面时，`fetch()` 读本地 JSON 会被 CORS 拦；
用 `http://127.0.0.1:<port>/` 提供则无障碍，且与「本地优先、零后端」定位一致。**只绑回环，绝不 0.0.0.0。**

**同时保留 `file://` 双击可用的兜底**：`build_viz_bundle.py` 除 `dashboard.json` 外还产出 `dashboard.js`
（`window.__SL_BUNDLE__ = {...}`，脚本标签不受 CORS 限制）；`index.html` 以 `<script src="data/dashboard.js">` 引入，
`app.js` 优先 `fetch` 取最新、失败则退回内联。→ 无需任何服务，双击 `index.html` 即可完整使用。

## 4. 数据束 schema 与**分区纪律**（合规硬要求）

`schema = summonerlens.dashboard.v1`。数据集分两类，**绝不混用**（承 A14 §5）：

| 数据集 | kind | 来源 | 是否入库 |
|---|---|---|---|
| `hero_ranking` / `augment_ranking` | `real_aggregate` | hexdata `data/agg/<buildId>/top_*.csv` | 源 CSV 入库 |
| `fixture_*`（hero/augment/item stats、三张组合表、player_mmr、slices） | `synthetic_fixture` | M3 `data/derived/m3/synthetic/` | 派生，不入库 |

- 每项带 `prov.kind/source/confidence`；真实数据另带 `buildId/reportPatch/reportDate/attribution`。
- 夹具数据集在前端**显著标注警示条**，`verify_m4.py` 断言两者的 `kind` **不得互换**。
- `alias_index` 归一化别名（去空白、小写）→ 英雄数值 `key`；来源 = `meta/aliases.csv` + hexdata `hero_aliases.csv`（462 条）。

## 5. 关键坑（**重要，勿踩**）

1. 🔴 **ECharts 不能在被 `display:none` 的面板里 init**：容器尺寸为 0 → 出现「坐标轴画了、柱体不可见」的假象。
   规矩：**先强制回流（读 `offsetHeight`）→ `chart.resize()` → 再 `setOption`**，并在切页后再兜一次 resize（`app.js` 的 `draw()`/`activateTab()`）。
2. 🔴 **类目轴上 `markLine.xAxis` 的数值会被当成「索引」**：传阈值数值（如 1712.1）会越界 → 线不画。
   规矩：传**分箱索引**（`core.js` 的 `snapIdx`）。
3. ⚠️ **真实聚合样本达百万级，Wilson 95% CI 窄到肉眼不可见**：不要用「区间带」表达，改用
   **浅色条 = 观测胜率 + 实色条 = Wilson 下界** 双条叠加（任何样本量都清晰，且下界更保守、跨样本可比）。
4. 🔴 **单测断言不得自洽**：若左右两边都由同一个（被篡改的）输入派生，故障注入不会变红。
   规矩：与**独立基准**比对 —— 用行内 `rank` 字段定名次、用 `dataset_index.*.rows` 定行数、
   用 `fixture_meta.strata.n` 定玩家数；并且「只留 X」类断言**必须同时断言非空**（`[].every()` 恒真）。
   → `test_m4_unit.js` 加固后，注入从 2 条变红提升到 **12 条**真变红。
5. ⚠️ **Flutter 命令一律走 `tools/flutter_task.py`**：它固定 cwd、写日志、限时、校验退出码，避免裸跑挂起会话。
   `run` 属 GUI 任务，无头会话下必须交给用户本地执行。

## 9. M4 补丁：webview 初始化竞态（2026-10-11，用户实测反馈后）

**现象**：桌面壳能启动（导航栏、顶栏、状态栏都在），但**内容区全黑**，状态栏报
`装载失败：LateInitializationError: Field '_methodChannel@46340896' has not been initialized`。

**根因（代码 bug，与「功能没写完」无关）**：`webview_windows` 的 `WebviewController`：

| 位置 | 代码 |
|---|---|
| `src/webview.dart:102` | `late MethodChannel _methodChannel;` |
| `src/webview.dart:175` | `_methodChannel = MethodChannel('$_pluginChannelPrefix/$_textureId');`（**只在 `initialize()` 内**） |
| `src/webview.dart:282` | `return _methodChannel.invokeMethod('loadUrl', url);` |

而 `ShellPage._boot()` 在 `setState(_baseUrl = url)` 之后**同一帧**就 `await _wc.loadUrl(...)`。
`setState` 只标脏，`DashboardWebview` 要到**下一帧**才挂载、`initialize()` 才被调用 ⇒ **竞态崩溃**。

**修复（4 点）**：
1. `DashboardWebview` 新增 **`onInitialized`** 回调，**只在 `await c.initialize()` 成功后**触发（父级此时才可调用 controller）。
2. webview **常驻挂载**（不再等 `baseUrl` 就绪），使其初始化与「起 Python 服务」**并行**，缩短首屏。
3. `_navigate()` 受 **`_webviewReady`** 门控；两条异步链路（起服务 / 初始化 webview）**谁后完成谁触发一次导航**。
4. `dispose()` 同样门控（未 `initialize` 就 `dispose()` 会命中同一个 late 字段）；另补 `onLoadError` 回调，导航错误只写状态栏、不替换视图。

**通用原则（→ kb M14）**：**「late 字段式」异步初始化必须"先就绪、后使用"**；跨组件协作时用**显式就绪回调 + 门控**，
不要依赖「setState 之后紧接着调用」这类帧序假设。

**验证状态**：✅ **已由用户本地验证通过（2026-10-11）**——用户执行 `build_desktop.bat` 重建后运行 `run_desktop.bat`，
桌面壳内容区**正常渲染**，`装载失败` 消失。修复有效，M4 正式闭环。
（过程：改动先经 `dart format` 语法校验；沙盒会话的 Dart 通道故障使 Agent 侧无法构建，见 §10。）

## 10. 环境故障：Dart 无法创建子进程（2026-10-11，排障记录）

- **现象**：本会话中 Dart/flutter **任何** spawn 子进程的操作都报
  `CreateFile failed 231（所有的管道范例都在使用中） at process_win.cc:744`；`dart format` / `dart --version`（不 spawn）**正常**。
- **对照实验**：**Python 创建子进程并捕获输出完全正常**（`PY_SPAWN_OK rc=0`）；系统命名管道仅 **237** 个 ⇒ **排除系统级管道耗尽**。
- **顺带修复的独立问题**：`mtkbtsvc.exe`（MediaTek 蓝牙服务）**句柄泄漏到 103,761**（系统总句柄 200,727，其独占 52%）。
  已 `Restart-Service mtkbtsvc`，系统句柄 **200,727 → ~97,000**。但 **Dart 故障未随之恢复**。
- **结论**：定位为 **WorkBuddy 沙盒会话级故障**（沙盒中心自身曾报 `sandbox-center cmd decisionRecord missing actual resource subject`）。
  **本会话内无法自愈**；需重启 WorkBuddy 会话，或由用户在本地终端执行构建。
- **处置**：新增 `build_desktop.bat`（本地双击重建：analyze + build + 结果判定）。
- **方法论**：环境类失败必须先隔离「代码问题 vs 环境问题」——用**另一语言/另一通道做对照实验**（此处 Python 成功即证伪了系统级假设）。
