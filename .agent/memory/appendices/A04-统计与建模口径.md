# A04 · 统计与建模口径

> 上级索引：`MEMORY.md` §1（A04）｜触发时机：写统计、排序、建模、标注之前｜相关：A02 数据、A03 技术栈

## 1. 排序与置信（治小样本霸榜）

- **排序方法**：`sample_tier_then_wilson_lower_bound_v1`（hexdata 同款思路）。
- **Wilson 95% 置信下界**：z = 1.96。胜率 `p`、样本 `n`：
  ```
  center = (p + z²/2n) / (1 + z²/n)
  margin = z·√(p(1-p)/n + z²/4n²) / (1 + z²/n)
  lower  = center - margin
  ```
- **样本分档**：低 `<250`；中 `250–999`；高 `≥1000`。
- **推荐门槛**：`≥250` 可推荐，`≥1000` 强推荐（低于门槛的胜率被 Wilson 下界压低，不让它霸榜）。

## 2. 自研指标（参考 hexdata）

- `HexScore`：相对英雄均值增益。
- `globalHexScore`：符文全局分。
- 本项目可沿用/改造，命名统一加前缀避免混淆。

## 3. 隐藏分 / MMR·ELO 反推（玩家分段维度）

- 海克斯大乱斗有**独立隐藏 MMR**，无排位分；模式初期偏低、场次越多越准；Riot 不公开数值。
- **可本地对个人对局做 ELO/MMR 估计**，再赋水平分层（前20% / 前40% / 全量）。简化更新：
  ```python
  def update_mmr(p, opp_avg, result, k=32):
      exp = 1 / (1 + 10 ** ((opp_avg - p) / 400))
      return round(p + k * (result - exp), 1)
  ```
- 这是 hexdata「海斗查分」的雏形，对接 A01 的「玩家分段」切片维度。

## 4. 英雄技能原型标注（M1 首个落地物，零对局数据依赖）

- 每位英雄 Q/W/E/R + 被动决定其定位；用 Data Dragon 技能描述打**技能原型标签**：
  `range / AoE / CC / sustain / mobility / burst`（可多选）。
- **价值**：把定性维度量化，与「强化符文路线」交叉（如高 Poke 英雄配哪类 Augment 胜率最高）；**不需对局数据即可先建**。
- 输出形态：静态标注表（CSV/JSON），随英雄池增量维护。
- ⚙️ **标签定义、判定规则、校订与验收流程见 A11**（173/173 已人工校订）。

## 5. 版本化与可溯源

- 每份数据带 `patch` / `date` / `buildId`；引用 hexdata 必带 `buildId + reportPatch + reportDate`（见 A02）。
- 地图维度：当前海克斯仅嚎哭深渊 1 张，架构预留 `map` 字段即可，勿过度设计（用户曾误记「三张地图」，实为 ARAM 家族整体轮换）。

## 6. 对局指标可信度（伤害 / 承伤，重要）

- 对局信息包含**伤害统计**与**承伤统计**；但 **WeGame 与掌上英雄联盟的数据来源都不一定准确**（结算面板与接口常不一致）→ **仅作参考**。
- 处理原则：**标注来源 + 交叉校验**（多源比对），偏差大者降级为低可信；**不把单一源当真相**。
- 自持/已授权对局可经**本地 LCU API** 取更全字段（含部分隐藏数据），但同样需校验。
