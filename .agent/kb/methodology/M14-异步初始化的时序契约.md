# M14 · 异步初始化的时序契约：先就绪、后使用

> 一句话：**「late 字段 + async initialize」类型的对象，必须等"就绪回调"到了再用；
> 不能假设「setState / 赋值之后紧接着调用」就已经可用。**

## 症状

- 运行时抛 `LateInitializationError: Field '_xxx' has not been initialized`，
  但代码里**明明写了** `await controller.initialize();`。
- 更迷惑的是：**有时能跑、有时不能**（取决于两件事谁先完成）。
- 报错位置常常离"写错的地方"很远 —— 错在**调用点**，但异常在**被调对象的内部字段**上炸。

真实案例（SummonerLens · M4）：

```dart
// 控制器内部（第三方插件 webview_windows）
late MethodChannel _methodChannel;              // webview.dart:102

Future<void> initialize() async {
  ...
  _methodChannel = MethodChannel('.../$_textureId');   // :175 —— 只有这里赋值
}

Future<void> loadUrl(String url) async {
  return _methodChannel.invokeMethod('loadUrl', url);  // :282 —— 直接使用
}
```

```dart
// 调用方（错的）
setState(() => _baseUrl = url);   // 只是"标脏"，下一帧才 build
await _wc.loadUrl(_url());        // 同一帧就调用 → Webview widget 还没挂载
                                  // → initialize() 还没被调用 → late 字段未赋值 → 崩
```

## 根因

三层叠加：

1. **对象内部把"初始化产物"声明成 `late`**（延迟到 `initialize()` 才赋值），**外部无法从字段本身判断就绪与否**。
2. **初始化是异步的**（`await`），从"发起"到"完成"之间有窗口期。
3. **调用方用"帧序/语句序"当同步点**：`setState` 只标脏，真正的 `build`（进而子组件 `initState` → `initialize()`）
   在**下一帧**；而 `await` 之前的那句话**已经执行完毕**了。

⇒ 于是 `loadUrl()` 落在窗口期内，命中未初始化的 `late` 字段。

## 规矩

1. **就绪必须以"显式信号"表达，不以"我调过初始化"表达。**
   由持有者（组件/服务）在初始化真正完成后发出回调 / 完成 Future / 置标志：
   ```dart
   await c.initialize();
   widget.onInitialized?.call();   // ← 这时才允许外部操作 controller
   ```
2. **调用侧一律门控**，把"未就绪"当成正常态而不是异常：
   ```dart
   Future<void> _navigate() async {
     if (_baseUrl == null || !_webviewReady) return;  // 门控
     await _wc.loadUrl(...);
   }
   ```
3. **两条独立异步链路，谁后完成谁触发动作**（不要赌顺序）：
   起服务完成 → 若 webview 已就绪则立即装载；webview 就绪 → 若服务已就绪则立即装载。
   两边都走同一个带门控的函数即可，天然幂等。
4. **让"初始化"尽早开始并常驻**：把重对象**常驻挂载**（不因其它前置条件未满足就晚挂载），
   让初始化与其它耗时步骤**并行**，既缩短首屏也缩小窗口期。
5. **销毁路径同样要门控**：未初始化就 `dispose()`，常常命中**同一个** `late` 字段（如
   `dispose()` 里 `await _creatingCompleter.future;`）。
6. **错误要降级而非替换视图**：导航类错误只写状态栏/日志，保留"重试"入口，
   不要把整个内容区换成错误页（否则用户无路可走）。

## 反例 / 检查清单

- [ ] 有没有 `late` 字段（或 `late final`）由 `async` 方法赋值，而其它方法直接读它？
- [ ] 调用点前面是不是只有 `setState(...)` / 赋值 / `addPostFrameCallback` 之外的**同帧**语句？
- [ ] 是否用 `if (isInitialized)` 这种**由自己维护**的标志，而不是靠"我调过 initialize 了"？
- [ ] 两条异步链路交叉时，**是否有第三种顺序能跑通**？（把两种完成顺序都走一遍）
- [ ] `dispose()` / `close()` 在"从未初始化"这条路径上会不会命中 `late`？
- [ ] 这个 bug 有**能变红的断言**吗？（M02/M11：能否构造出 100% 复现的最小样例）

## 顺带：怎么快速判定"是代码还是环境"

本次同场还遇到一个**纯环境**故障（Dart 无法创建子进程），排查方式可复用：

1. **换语言做对照**：Python 创建子进程成功 ⇒ 证伪"系统级资源耗尽"。
2. **数系统资源**：命名管道 237 个（正常）、句柄总数（发现某服务独占 52%）。
3. **换通道**：bash / PowerShell / WMI 三条路都试，区分"我的调用方式"与"环境本身"。
4. 结论：不要在同一通道反复重试超过 2 次；**换对照实验比重复重试信息量大得多**。
