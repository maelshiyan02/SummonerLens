# M13 · 图表渲染的三个静默陷阱（尺寸 / 类目轴 / 尺度）

> **症状** 页面没报错、控制台干净，但图"看着不对劲"：柱子没了、参考线不画、置信区间看不见。
> 三个陷阱都**不抛异常**，只会让图变错或变空 —— 属于典型的静默分歧（见 M03）。

---

## 陷阱 1：在被隐藏的容器里初始化图表 → 柱子静默消失

**症状**：`display:none` 的面板里（或 tab 未激活时）`echarts.init(container)`，切到该面板后
**坐标轴、网格线、类目名都画出来了，但系列（柱/线）不见**。控制台无任何报错。

**根因**：`init` 时容器 `offsetWidth/offsetHeight` 为 0，引擎按 0 尺寸建画布；之后即使容器变可见，
若不触发 `resize()`，系列就画在 0 尺寸的坐标系里。坐标轴文字因为走另一套布局路径仍会渲染，
于是形成"轴在、数据不在"的假象。

**规矩**
1. 切面板时**先强制回流**（读一次 `el.offsetHeight`）再渲染；
2. 每次绘制前**先 `chart.resize()` 再 `setOption()`**（封装成 `draw(id, option)` 统一入口）；
3. 切页后再兜一次 `resize`（延迟 ~60ms）。

**检查清单**：任何"标签页/折叠面板里的图表"都要能在**首次直接激活**时正确出图（用 URL 参数直达该页做回归）。

---

## 陷阱 2：类目轴上 `markLine.xAxis` 的数值被当成「索引」

**症状**：想在柱状图（类目轴）上画一条阈值参考线，传了阈值的**真实数值**（如 `xAxis: 1712.1`），
线**完全不画**，也没有任何警告。传 `1700`（同样是数值）也不画。

**根因**：类目轴上 `markLine`/`markPoint` 的 `xAxis` 语义是 **类目索引**，不是数值。数值超出类目数量即越界被丢弃。

**规矩**：把阈值**映射为分箱索引**再传：`idx = clamp(round((value - lo) / bin), 0, bins-1)`；
标签上仍显示真实阈值，避免读图误解。若确实想按数值定位，就把该轴改成 `type:'value'`。

**检查清单**：断言"参考线落在 `[0, 类目数-1]` 内"，并断言线条数量符合预期。

---

## 陷阱 3：把「置信区间」画成区间带 —— 大样本下窄到看不见

**症状**：用「透明底条 + 彩色跨度条」表达 95% CI；样本量到百万级时 CI 宽度约 0.1%，
**视觉上完全消失**，看起来像图坏了。

**根因**：区间宽度随 `1/√n` 收缩；n 从 10⁴ 到 10⁶，带宽缩到 1/10。用"宽度"编码一个跨数量级变化的量，
在大样本端必然退化。

**规矩**：用**两条叠加条**代替区间带 —— 浅色条 = 观测值（原始胜率），实色条 = 下界（保守排序信号）。
两者之差本身就是"不确定性"，且**跨样本量可比**；完整 CI 放进 tooltip。

**检查清单**：让**同一种图**既能画 n=44 的小样本，也能画 n=1.8e6 的大样本，都不能"看起来是空的"。

---

## 附：这三条为什么值得单独成篇

它们共享一个特征：**错误不报错**。所以不能靠"跑起来没报错"判断正确，只能靠
**按视图做渲染抽查 + 断言参考线/系列数量**（见 M01/M02/M11）。凡是"看起来正常但可能悄悄画空"的图，
都必须有一条能在它画空时变红的断言。
